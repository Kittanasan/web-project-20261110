# นำโฟลเดอร์นี้ขึ้นเว็บไซต์ (ฉบับทำตามได้เลย)

ระบบแยกเป็น 2 ส่วน เพื่อให้เปิดหน้าเว็บจากที่ไหนก็ได้ แต่ยังใช้แบบจำลอง YOLO ที่ต้องมี torch:

| ส่วน | ไฟล์ | ทำหน้าที่ |
|---|---|---|
| **ฝั่งเว็บไซต์ (คลาวด์)** | `cloud_app.py` | หน้าเว็บ + **ฐานข้อมูลกลาง** `data/db.sqlite` + เก็บภาพ/รายงานใน `exports/` |
| **เครื่องประมวลผล (ในศูนย์)** | `app.py` + `liverV1.pt` | วิเคราะห์ภาพด้วยแบบจำลองจริง (torch + ultralytics) |

หน้าเว็บคุยกับทั้งสองฝั่งเอง: เก็บข้อมูล/ตารางที่ฐานข้อมูลกลาง และส่งภาพไปประเมินที่เครื่องประมวลผล

---

## ฐานข้อมูล: มีอยู่แล้วในโฟลเดอร์นี้ ไม่ต้องดึงจากที่อื่น

- ไฟล์จริง: `data/db.sqlite` (SQLite — ไม่ต้องติดตั้ง MySQL/Postgres)
- ตาราง `samples` = ผลตรวจ (ลำดับที่ / label / ฟาร์ม / ผล / ความเชื่อมั่น / ผู้ตรวจ / ภาพ / รายงาน)
- ตาราง `farmers` = ทะเบียนฟาร์ม (เติมอัตโนมัติในช่อง "ฟาร์มที่มาของตัวอย่าง")
- ข้อมูลตั้งต้นถูกสร้างด้วย `python prepare_cloud_folder.py` แล้ว และมีไฟล์ `data/seed_report.json`
  ให้เปิดดูได้โดยไม่ต้องรันโปรแกรม
- สำรองข้อมูล: ดับเบิลคลิก `สำรองฐานข้อมูล.bat` → ได้ `data/backup-<วันเวลา>.json`
- กู้คืน: ดับเบิลคลิก `คืนค่าฐานข้อมูล.bat`

---

## วิธีที่ 1 — เปิดเว็บบนเครื่องนี้ (ไม่ต้องมีอินเทอร์เน็ต)

ดับเบิลคลิก `start.bat` (เหมือนเดิม) แล้วใช้ `http://127.0.0.1:8000`
ตัวนี้ทำงานครบทั้งหน้าเว็บ + ฐานข้อมูล + ประเมินภาพ (ต้องมี `runtime/` ที่มี torch)

## วิธีที่ 2 — ขึ้นเว็บจริงด้วย Render (ฟรี) + เครื่องในศูนย์เป็นตัวประเมิน

1. อัปโฟลเดอร์นี้ขึ้น GitHub (**`liverV1.pt` 6.2 MB ขึ้นไปด้วย** — ไม่ได้ถูกกันใน `.gitignore` แล้ว,
   กันไว้เฉพาะ `runtime/`) ต้องการให้เว็บประเมินภาพเองต้องติดตั้ง torch + ultralytics ซึ่งอยู่ใน `requirements.txt` แล้ว
2. ที่ render.com → **New → Web Service** → เลือก repo นี้
   - Build command: `pip install -r requirements.txt`
   - Start command: `python cloud_app.py` (มีใน `Procfile` แล้ว)
3. ตั้ง Environment Variables
   - `LIVER_ENGINE` = ที่อยู่ของเครื่องประมวลผล เช่น `https://abc-def.trycloudflare.com`
   - `LIVER_SECRET` = รหัสผ่านสำหรับแก้/ลบข้อมูล (ตั้งเป็นความลับ)
   - ไม่ต้องตั้ง `LIVER_ENGINE` ถ้าอยากให้เว็บประเมินภาพเองด้วย `liverV1.pt` (ต้องมี torch, build จะนานขึ้นมาก)
4. เปิด URL ที่ Render ให้มา → หน้าเว็บขึ้น พร้อมตารางผลตรวจจาก `data/db.sqlite`

### เปิดเครื่องประมวลผลให้คลาวด์เรียกได้ (ทำที่เครื่องในศูนย์)

```
start.bat                          (เปิด app.py ตามปกติ พอร์ต 8000)
cloudflared tunnel --url http://127.0.0.1:8000
```
คัดลอก URL ที่ได้ (ขึ้นต้น `https://…trycloudflare.com`) ไปใส่ `LIVER_ENGINE`
ในหน้า Render แล้วกด Redeploy — ทดสอบด้วย `https://<เว็บ>/health` ต้องเห็น
`"engine": {"ok": true, "lib_ok": true}`

> หมายเหตุ: ถ้าไม่ตั้ง `LIVER_ENGINE` เว็บจะยังใช้ได้ (บันทึก/แก้/ลบ/ดูตาราง/พิมพ์รายงาน)
> แต่กด "ประเมินภาพ" ไม่ได้ และจะขึ้นข้อความบอกสาเหตุตรง ๆ

## วิธีที่ 3 — ให้คลาวด์ประเมินภาพเอง (ไม่ต้องพึ่งเครื่องในศูนย์)

เปิด 2 บรรทัดท้ายของ `requirements.txt` (`torch`, `ultralytics`) แล้วอัป `liverV1.pt` ขึ้นโฮสต์ด้วย
(**ต้องใช้โฮสต์ที่มี RAM ≥ 2 GB** — แพ็กเกจฟรีของ Render อาจไม่พอ)

## ตรวจว่าโฟลเดอร์พร้อมหรือยัง

```
python check_cloud_db.py               # ตรวจไฟล์ฐานข้อมูลจริง + ไฟล์ที่โฮสต์ต้องใช้ (ไม่ต้องเปิดเซิร์ฟเวอร์)
python test_cloud_api.py 8080          # ทดสอบฝั่งเว็บ (ฐานข้อมูล/บันทึก/แก้/ลบ) — ต้องเปิด cloud_app.py ก่อน
python test_cloud_relay.py 8081 http://127.0.0.1:8000   # ทดสอบเว็บ -> เครื่องประมวลผล
```

### เปิดเว็บฝั่งคลาวด์ในเครื่องตัวเองก่อนอัปจริง

```
python cloud_app.py        -> http://127.0.0.1:8080
```
จะเห็นตารางผลตรวจ 6 แถวจาก `data/db.sqlite` ตั้งแต่เปิดครั้งแรก (ไม่ต้องกดอะไรเพิ่ม)

### ย้ายไปเครื่องอื่นแบบไม่ต้องติดตั้งอะไรเลย

1. คัดลอกทั้งโฟลเดอร์ไป (หรือโหลดจาก GitHub) — ฐานข้อมูล `data/db.sqlite` และภาพใน `exports/` ไปด้วย
2. ถ้าต้องการฐานข้อมูลว่างใหม่: ลบ `data/db.sqlite*` แล้วรัน `python prepare_cloud_folder.py`
3. ถ้าต้องการยกข้อมูลจากเครื่องเดิม: `python backup_db.py backup` ที่เครื่องเดิม แล้วนำ `data/backup-*.json` ไปวางที่เครื่องใหม่แล้ว `python backup_db.py restore`

## ข้อควรรู้เรื่องพื้นที่เก็บข้อมูลบนคลาวด์

- Render/Railway แพ็กเกจฟรี: ไฟล์ที่เขียนลงดิสก์ (ฐานข้อมูล/ภาพ) **หายเมื่อรีสตาร์ต**
  → ใช้ปุ่ม **"ส่งออกทั้งหมด (JSON)"** บนหน้าเว็บเก็บสำเนาไว้ทุกครั้ง หรืออัปเกรดเป็นแบบมี Disk
- ถ้าต้องการฐานข้อมูลออนไลน์ถาวร (หลายคนใช้พร้อมกัน) บอกได้ จะเปลี่ยน `db.py` ให้ต่อ PostgreSQL/Supabase
